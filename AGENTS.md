# AGENTS.md — Contributor & Agent Guide

This repository manages the `terlar` GitHub account on `github.com` as code
using [OpenTofu](https://opentofu.org/). All repositories and branch protection
rules are declared in HCL and applied via a GitHub Actions pipeline.

---

## Developer Environment

The dev environment is provided entirely through the **Nix flake**. Enter it with:

```bash
nix develop        # manually enter the devshell
# or, with direnv:
direnv allow       # auto-activates on directory entry
```

Commands available inside the devshell (`menu` to list):

| Command      | Description                        |
|--------------|------------------------------------|
| `menu`       | Print the help menu                |
| `pre-commit` | Manage and run pre-commit hooks    |
| `treefmt`    | Format all files in-place          |

## Build / Check / Lint / Format

### CI check

```bash
nix flake check --print-build-logs
```

Validates all Nix flake outputs including the `tofu` package. Run this locally
before opening a PR.

### Format all files

```bash
treefmt                    # format in-place
treefmt --fail-on-change   # check only (used in pre-commit hook)
```

`treefmt` delegates to `nixfmt` for `*.nix` files. HCL and YAML files are not
auto-formatted — keep them consistent with the existing style by hand.

### Pre-commit hooks

Pre-commit hooks are **auto-generated by Nix** — do not edit `.pre-commit-config.yaml`
directly. Hooks run automatically on `git commit`. To run all hooks manually:

```bash
pre-commit run --all-files
```

Hooks include:
- `check-yaml` — validates YAML (multi-document aware)
- `check-merge-conflicts` — detects unresolved conflict markers
- `end-of-file-fixer` — ensures files end with a newline
- `treefmt` — formatting enforcement
- `conform` (commit-msg stage) — commit message policy
- `first-ci-kit-gen-github-actions` — regenerates workflow YAML from `dev/ci.nix`

## Making Changes

### Adding or updating a repository

Edit `terraform/terraform.tfvars` — add or modify an entry in the `repositories`
map, then open a PR. The plan is posted as a PR comment; merge to apply.

### Importing an existing resource

Add a declarative `import {}` block to `terraform/import.tf`, open a PR, verify
the plan shows only an import (no destructive changes), then apply. Delete the
block after the apply succeeds.

## Running OpenTofu Locally

All `tofu` commands that touch the backend are wrapped transparently by the
`tofu` Nix package. Export credentials first:

```bash
export TF_VAR_github_app_id="<app-id>"
export TF_VAR_github_app_installation_id="<installation-id>"
export TF_VAR_github_app_pem_key="$(cat /path/to/private-key.pem)"
export TF_VAR_state_encryption_passphrase="<passphrase>"
export GIT_USERNAME="x-access-token"
export GIT_PASSWORD="<github-token-with-contents-rw-on-terraform-state>"
```

Run all commands from the `terraform/` directory:

```bash
cd terraform

nix run ..#tofu -- init -input=false
nix run ..#tofu -- validate
nix run ..#tofu -- plan -input=false
nix run ..#tofu -- apply -auto-approve -input=false
```

The `tofu` wrapper only intercepts subcommands that touch the backend
(`init`, `plan`, `apply`, `destroy`, `import`, `state`, `output`, `refresh`).
Everything else is passed straight to `opentofu`.

## Commit Message Policy

Enforced by `conform` (runs as a `commit-msg` git hook). Non-conforming commits
are **rejected**.

**Format:** `<type>: <lowercase imperative description>`

```
feat: add resume repository
fix: correct branch protection required checks
ci: add apply step on push to main
docs: update local run instructions in AGENTS.md
```

### Rules

- **Types:** `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`,
  `style`, `test`
- **Header max length:** 89 characters
- **Description max length:** 72 characters
- **Case:** subject line must start **lowercase**
- **Mood:** imperative (`add`, not `adds` or `added`)
- **No trailing period** at end of subject line

## Code Style

### HCL (`terraform/`)

- **2-space indentation** throughout.
- Align `=` signs within a block where it aids readability.
- Use `for_each` driven by input variables — avoid hard-coded resource blocks.
- Mark sensitive variables with `sensitive = true`.
- Keep `terraform.tfvars` free of secrets — secrets are passed via environment
  variables (`TF_VAR_*`) or Actions secrets.

### YAML (`.github/workflows/`)

- **2-space indentation** throughout.
- Workflows are **auto-generated** from `dev/ci.nix` — do not edit manually.
- Edit `dev/ci.nix` and run `pre-commit run --all-files` to regenerate.

### Nix (`flake.nix`, `dev/`)

- Formatted by `nixfmt` (RFC-style); let the formatter handle all whitespace.
- Follow `flake-parts` / `perSystem` patterns consistent with the existing `flake.nix`.
- Avoid unused `let` bindings and unused function arguments (`deadnix` will catch them).
- Avoid Nix anti-patterns (`statix` will catch them).

## Dependency Management

- **Nix inputs** are pinned in `flake.lock` and `dev/flake.lock`. Update with
  `nix flake update` (or selectively: `nix flake update <input>`). Always commit
  `flake.lock` changes.
- **GitHub Action versions** in generated `workflows/` use `@v<N>` tags — update
  them in `dev/ci.nix`.
- **OpenTofu provider versions** are pinned in `terraform/versions.tf` via
  `required_providers`.
