# AGENTS.md — Contributor & Agent Guide

This repository manages the `terlar` GitHub account on `github.com` as code
using [OpenTofu](https://opentofu.org/). All repositories and branch protection
rules are declared in HCL and applied via a GitHub Actions pipeline.

---

## Build / Check / Lint / Format

### CI check (run before opening a PR)

```bash
nix flake check --print-build-logs
```

### Format all files

```bash
treefmt                    # format in-place
treefmt --fail-on-change   # check only
```

`treefmt` delegates to `nixfmt` for `*.nix` files. HCL and YAML are not
auto-formatted — keep them consistent by hand.

### Pre-commit hooks

**Auto-generated by Nix** — do not edit `.pre-commit-config.yaml` directly.

```bash
pre-commit run --all-files   # run all hooks manually
```

Hooks: `deadnix`, `statix`, `treefmt`, `check-yaml`, `check-merge-conflicts`,
`end-of-file-fixer`, `conform` (commit-msg), `first-ci-kit-gen-github-actions`.

### Running OpenTofu locally

```bash
export TF_VAR_github_app_id="<app-id>"
export TF_VAR_github_app_installation_id="<installation-id>"
export TF_VAR_github_app_pem_key="$(cat /path/to/private-key.pem)"
export TF_VAR_state_encryption_passphrase="<passphrase>"
export GIT_USERNAME="x-access-token"
export GIT_PASSWORD="<github-token>"

cd terraform
nix run ..#tofu -- init -input=false
nix run ..#tofu -- validate
nix run ..#tofu -- plan -input=false
```

The `tofu` wrapper intercepts backend-touching subcommands
(`init`, `plan`, `apply`, `destroy`, `import`, `state`, `output`, `refresh`).

## Making Changes

### Adding or updating a repository

Edit `terraform/terraform.tfvars` — add or modify an entry in the `repositories`
map, then open a PR. The plan is posted as a PR comment; merge to apply.

### Importing an existing resource

Add a declarative `import {}` block to `terraform/import.tf`, open a PR, verify
the plan shows only an import (no destructive changes), then apply. Delete the
block after the apply succeeds.

**Branch protection import ID format:** `"repo-name:branch"` (e.g., `"archbox:main"`).

## Commit Message Policy

Enforced by `conform` (commit-msg git hook). Non-conforming commits are **rejected**.

**Format:** `<type>: <lowercase imperative description>`

- **Types:** `build`, `chore`, `ci`, `docs`, `feat`, `fix`, `perf`, `refactor`, `style`, `test`
- **Header max length:** 89 characters
- **Case:** must start **lowercase**, imperative mood, no trailing period

## Code Style

### HCL / Terraform

- **2-space indentation**. Align `=` signs within blocks for readability.
- **File organization:** one concern per file (`repositories.tf`, `branch_protection.tf`, etc.).
- **`for_each` pattern:** all resources driven by input variables — no hard-coded blocks.
- **`optional(type, default)`:** use for all object attributes, keeping defaults centralized.
- **`coalesce` for fallbacks:** `coalesce(each.value.visibility, var.default_repo_visibility)`.
- **Dynamic blocks:** use for optional nested blocks (`dynamic "pages"`, `dynamic "required_status_checks"`).
- **Lifecycle blocks:** use `ignore_changes = [name]` to prevent accidental renames.
- **No secrets in tfvars:** pass via `TF_VAR_*` environment variables.

### Branch protection gotchas

- `repository_id` must be **just the repo name** (`each.key`), NOT `"owner/repo"`.
  The provider auto-prepends the owner. Using `"terlar/${each.key}"` causes
  double-prefix errors like `terlar/terlar/repo-name`.
- **Archived repos cannot have branch protection.** The `local.protected_repos`
  filter excludes `cfg.archived` repos automatically.

### Nix

- Formatted by `nixfmt` (RFC-style) — let the formatter handle whitespace.
- Follow `flake-parts` / `perSystem` patterns.
- Avoid unused bindings/arguments (`deadnix` and `statix` will catch them).
- Use `imports = [...]` for module composition, `follows` for input alignment.

### YAML / GitHub Workflows

- **Auto-generated from `dev/ci.nix`** — never edit manually.
- Edit `dev/ci.nix` and run `pre-commit run --all-files` to regenerate.

## Dependency Management

- **Nix inputs** pinned in `flake.lock` and `dev/flake.lock`. Update with
  `nix flake update`. Always commit lock changes.
- **GitHub Action versions** use `@v<N>` tags — update in `dev/ci.nix`.
- **Provider versions** pinned in `terraform/versions.tf`.
